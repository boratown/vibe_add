## Phase 2: 핵심 데이터 계층 (P1)

- [x] T004 ORM 모델과 스키마를 정의한다. 완료 조건: Todo 엔티티가 생성되고, 제목/완료 여부 필드가 정상 반영된다.
- [x] T005 데이터베이스 세션과 초기화를 구성한다. 완료 조건: 테스트 실행 시 SQLite 데이터베이스가 생성된다.
- [x] T006 CRUD 로직을 구현한다. 완료 조건: 목록 조회, 생성, 완료 토글, 삭제가 각각 정상 동작한다.

---

## Phase 3: 사용자 스토리 1 - 할 일 추가 및 입력 검증 (Priority: P1)

**Goal**: 사용자가 새 할 일을 추가하고 빈 제목을 거절받을 수 있게 한다.

### 구현 태스크

- [x] T007 목록 조회 API를 구현한다. 완료 조건: `GET /api/todos`가 목록을 반환한다.
- [x] T008 생성 API를 구현한다. 완료 조건: `POST /api/todos`가 새 할 일을 저장하고, 빈 제목은 `422`를 반환한다.
- [x] T009 남은 할 일 개수 계산 로직을 연결한다. 완료 조건: 생성 후 응답 기준으로 남은 개수가 올바르게 반영된다.

---

## Phase 4: 사용자 스토리 2 - 상태 변경 및 삭제 (Priority: P1)

**Goal**: 사용자가 할 일을 완료/복원하고 삭제할 수 있게 한다.

### 구현 태스크

- [x] T010 완료 토글 API를 구현한다. 완료 조건: `PATCH /api/todos/{id}`로 완료 상태가 바뀐다.
- [x] T011 삭제 API를 구현한다. 완료 조건: `DELETE /api/todos/{id}`가 삭제하고, 없는 ID는 `404`를 반환한다.
- [x] T012 완료/삭제 후 목록 갱신 흐름을 구현한다. 완료 조건: 상태 변경 후 목록이 즉시 갱신된다.

---

## Phase 5: 사용자 스토리 3 - 필터링, 영속성, 빈 상태 (Priority: P2)

**Goal**: 사용자가 필터를 바꾸고, 새로고침 후에도 데이터를 유지하며, 빈 상태를 확인할 수 있게 한다.

### 구현 태스크

- [x] T013 필터 쿼리 파라미터를 지원한다. 완료 조건: `status=all|active|completed`에 따라 조회 결과가 다르게 나온다.
- [x] T014 데이터 영속화를 위한 DB 저장 흐름을 연결한다. 완료 조건: 앱 재시작 후에도 저장된 할 일이 유지된다.
- [x] T015 빈 상태 안내를 구현한다. 완료 조건: 할 일이 없을 때 사용자에게 적절한 안내 문구가 보인다.

---

## Phase 6: 화면(UI) 및 통합 검증 (Priority: P2)

- [x] T016 메인 화면 템플릿을 구현한다. 완료 조건: HTML 화면이 정상 렌더링된다.
- [x] T017 바닐라 JavaScript로 목록·필터·남은 개수·삭제 확인을 연동한다. 완료 조건: 페이지 새로고침 없이 UI가 갱신된다.
- [x] T018 통합 테스트를 추가한다. 완료 조건: 생성, 조회, 토글, 삭제, 필터 흐름이 모두 통과한다.

# 기능 명세서: 오늘의 할 일 웹 앱

**Feature Branch**: `001-todo-list-app`

**Created**: 2026-07-15

**Status**: Draft

**Input**: 사용자 설명: "오늘의 할 일" 웹 앱을 만들려고 해. 사용자 관점의 요구사항은 다음과 같아.

## 사용자 시나리오 및 테스트 *(필수)*

### 사용자 스토리 1 - 할 일 추가 및 입력 검증 (Priority: P1)
사용자는 새 할 일을 입력하고 목록에 추가할 수 있다. 빈 값이나 공백만 있는 입력은 거절되고, 즉시 안내 메시지를 받아 문제를 바로 이해할 수 있다.

**Why this priority**: 이 기능은 앱의 핵심 가치를 제공하므로 가장 높은 우선순위를 가진다.

**Independent Test**: 사용자가 하나의 유효한 할 일을 추가할 수 있고, 잘못된 입력에 대해 안내를 받는 방식으로 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 할 일 목록이 비어 있는 상태일 때, **When** 사용자가 유효한 할 일을 입력하고 추가하면, **Then** 목록에 새 항목이 나타나고 남은 할 일 수가 갱신된다.
2. **Given** 입력란이 비어 있거나 공백만 입력된 상태일 때, **When** 사용자가 추가를 시도하면, **Then** 새 항목은 추가되지 않고 안내 메시지가 표시된다.

---

### 사용자 스토리 2 - 할 일 상태 관리 및 삭제 (Priority: P1)
사용자는 할 일을 완료 처리하거나 다시 미완료 상태로 되돌릴 수 있고, 완료된 항목은 시각적으로 구분된다. 또한 실수 방지를 위해 삭제 전 확인 절차를 거친 후 항목을 제거할 수 있다.

**Why this priority**: 상태 전환과 삭제는 일상적인 작업 흐름의 핵심이며, 사용자가 앱를 자주 사용하는 주요 이유가 된다.

**Independent Test**: 완료/미완료 전환, 완료 항목의 시각적 표시, 삭제 확인 절차를 개별적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 목록에 미완료 항목이 있을 때, **When** 사용자가 해당 항목을 완료 처리하면, **Then** 항목은 완료 상태로 표시되고 남은 할 일 수가 줄어든다.
2. **Given** 완료된 항목이 있을 때, **When** 사용자가 해당 항목을 다시 미완료 상태로 전환하면, **Then** 항목은 일반 상태로 돌아오고 남은 할 일 수가 다시 증가한다.
3. **Given** 삭제하려는 항목이 있을 때, **When** 사용자가 삭제를 시도하면, **Then** 삭제를 확인하는 절차가 표시되고, 확인하지 않으면 항목이 유지된다.

---

### 사용자 스토리 3 - 목록 필터링, 상태 유지 및 빈 상태 안내 (Priority: P2)
사용자는 전체, 진행 중, 완료된 항목만 필터링해서 볼 수 있고, 페이지를 새로고침하거나 앱을 다시 시작해도 기존 할 일 목록이 유지된다. 할 일이 하나도 없을 때는 명확한 빈 상태 안내를 받는다.

**Clarification**: 데이터 저장 방식은 브라우저의 로컬 저장을 우선 사용한다. 이 방식으로 새로고침과 브라우저 재시작 후에도 할 일 목록이 유지되도록 한다.

**Why this priority**: 이 기능들은 사용 편의성과 신뢰성을 높여 앱의 전반적인 만족도를 개선한다.

**Independent Test**: 필터 변경, 데이터 유지, 빈 상태 안내가 각각 독립적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 여러 상태의 할 일이 있을 때, **When** 사용자가 필터를 변경하면, **Then** 선택한 필터에 해당하는 항목만 표시된다.
2. **Given** 할 일 목록에 변경이 발생한 상태일 때, **When** 사용자가 페이지를 새로고침하거나 앱을 다시 시작하면, **Then** 이전 목록 상태가 유지되어 다시 표시된다.
3. **Given** 등록된 할 일이 하나도 없을 때, **When** 사용자가 화면을 확인하면, **Then** 친절한 빈 상태 안내 문구가 표시된다.

---

### Edge Cases

- 입력란에 공백만 입력된 경우에는 항목이 추가되지 않아야 한다.
- 삭제 확인 절차를 취소한 경우에는 항목이 유지되어야 한다.
- 필터가 현재 표시된 항목 수와 일치하도록 동작해야 한다.
- 필터 조건에 해당하는 항목이 없을 때는 해당 필터에 맞는 빈 상태 안내가 표시되어야 한다.
- 할 일이 없을 때는 빈 상태 안내만 표시되어야 하며, 목록 영역이 비어 있어야 한다.

## 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 사용자는 새 할 일을 입력하고 추가할 수 있어야 한다.
- **FR-002**: 빈 값 또는 공백만 있는 입력은 거절되어야 하며, 사용자에게 안내 메시지를 보여주어야 한다.
- **FR-003**: 사용자는 할 일을 완료 상태로 변경할 수 있어야 하며, 완료된 항목은 취소선과 흐린 색상으로 명확하게 구분되어야 한다.
- **FR-004**: 사용자는 완료된 할 일을 다시 미완료 상태로 되돌릴 수 있어야 한다.
- **FR-005**: 사용자는 할 일을 삭제할 수 있어야 하며, 삭제 전 확인 절차를 거쳐야 한다. 사용자가 확인을 취소하면 항목은 유지되어야 한다.
- **FR-006**: 화면 상단에는 남은 할 일 개수가 항상 표시되어야 하며, 추가, 완료, 삭제가 발생할 때 즉시 갱신되어야 한다.
- **FR-007**: 사용자는 전체 / 진행중 / 완료 3가지 필터로 목록을 확인할 수 있어야 하며, 필터 변경 시 해당 조건의 항목만 표시되어야 한다.
- **FR-008**: 할 일 목록은 새로고침이나 앱 재시작 후에도 유지되어야 하며, 브라우저 로컬 저장소를 이용해 영속화한다.
- **FR-009**: 화면은 모바일 화면에서도 사용할 수 있어야 하며, 기본 동작이 깨지지 않아야 한다.
- **FR-010**: 할 일이 하나도 없을 때는 빈 상태 안내 문구를 표시해야 하며, 예시 문구로 “아직 등록된 할 일이 없습니다. 새 할 일을 추가해보세요.”를 사용할 수 있다.
- **FR-011**: 잘못된 할 일 식별자나 요청에 대해서는 오류 메시지를 표시하고, 목록 상태는 유지되어야 한다.

### 핵심 엔티티

- **할 일(Todo)**: 사용자가 관리하는 작업 항목으로, 내용과 완료 여부를 포함한다.
- **할 일 목록(Todo List)**: 여러 할 일 항목이 모여 있는 사용자 화면의 기본 집합이다.
- **필터(Filter)**: 전체, 진행 중, 완료 상태 중 하나를 선택해 목록을 좁혀 보는 기준이다.

## 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 사용자는 첫 사용 시 1분 이내에 새 할 일을 하나 이상 추가할 수 있어야 한다.
- **SC-002**: 사용자가 페이지를 새로고침하거나 브라우저를 다시 시작한 뒤에도 기존 할 일 목록이 그대로 유지되어야 한다.
- **SC-003**: 360px 폭 화면에서도 주요 조작이 모두 접근 가능하고, 가로 스크롤 없이 사용할 수 있어야 한다.
- **SC-004**: 할 일이 없을 때 사용자는 명확한 빈 상태 안내를 보고 다음 행동을 이해할 수 있어야 한다.

## 가정사항

- 사용자는 개인용 작업 관리 목적의 단일 사용자 환경을 기준으로 앱를 사용하는 것으로 가정한다.
- 할 일 내용은 짧은 텍스트 중심으로 입력되며, 첨부파일이나 기한 설정 같은 고급 기능은 이번 범위에 포함되지 않는다.
- 사용자의 브라우저는 정상적으로 상태를 유지할 수 있는 환경에서 사용된다고 가정한다.
- 데이터 저장은 브라우저 로컬 저장소 기반으로 처리하며, 서버 연동이나 다중 기기 동기화는 이번 범위에 포함하지 않는다.
- 기술 스택은 이 단계에서 정하지 않으며, 이후 계획 단계에서 결정한다.
